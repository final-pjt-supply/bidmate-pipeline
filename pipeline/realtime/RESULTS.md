## 확장자-실제 포맷 불일치로 인한 오탐 라우팅 위험 (2026-07-10 발견)

**증상**: 파일 확장자와 실제 포맷이 불일치하는 케이스 존재 — `.hwpx` 확장자인데
실제 내용은 hwp 포맷, 반대로 `.hwp` 확장자인데 실제 내용은 hwpx 포맷.

**위험**: pdf/hwp/hwpx 큐 라우팅이 S3 key의 확장자(`{file_id}.{ext}`)만 보고
`raw/downloads/daily/.../{file_id}.hwpx` → `realtime-extract-hwpx-queue`처럼
정해진다(`파일 확장자 기반, 실제 포맷 검증 없음). 확장자와 실제 포맷이 다르면
잘못된 추출기(hwp 추출기가 실제 hwpx 파일을, 또는 그 반대)로 넘어가고, 에러 없이
깨진/불완전한 텍스트가 조용히 `extracted/`에 저장될 수 있음(예외를 던지지 않는
포맷 파서라면 특히 위험 — 실패가 아니라 오탐이라 감지가 더 어려움).

**해결 방향(추후)**: 확장자 대신 매직 넘버로 실제 포맷을 감지해서 라우팅/파싱 결정.
- ZIP 계열 시그니처(`PK`/`0x504B`) → hwpx(OOXML 기반)
- OLE 계열 시그니처(`0xD0CF11E0`) → hwp(구 바이너리 포맷)

**발견 경위 및 규모**: 체계적 전수 스캔이 아니라 파일을 수동으로 열어보다 우연히
발견된 것 — 전체 raw 문서(68~69건) 중 몇 건이 실제로 확장자-포맷 불일치인지는
아직 미파악. 매직 넘버 기반 전수 스캔을 돌리면 정확한 규모를 확인할 수 있음
(스캔 자체는 이 수정과 별개로 먼저 해볼 수 있는 저위험 작업).

**현재 상태**: 미수정. 2026-07-09~10 IAM 권한 누락으로 인한 403/DLQ 적체 인시던트
대응이 우선이라 그것부터 마무리한 뒤 별도로 다룬다.

**실제 영향 확인(2026-07-10)**: IAM 수정 검증 중 hwpx-dlq에서 임의로 고른 1건
(`R26BK01625116_000/doc01`, `.hwpx` 확장자)이 우연히 이 케이스였음을 확인 —
`zipfile.BadZipFile: File is not a zip file`로 **예외 발생, 처리 완전 실패**
(조용히 깨진 텍스트가 아니라 확실한 크래시로 나타남). hwpx-dlq 전량 redrive
검증 결과 **고유 문서 33건**이 전부 이 케이스로 확인됨(#62 인시던트 대응 중
실측, hwp/pdf는 재시도 주기가 안 끝나 미확정).

## DLQ 알람 구성 불균일 — 단계별 감시 수준 재정비 필요 (2026-07-10, #62 후속)

**현재 상태**: #62 대응으로 DLQ 알람 6개 전부 SNS(`realtime-pipeline-alerts`)
이메일 연결 완료(감시 공백 자체는 해소). 다만 파이프라인 단계별 구성이
불균일함:
- LLM 단계: DLQ has-messages + 큐 적체(backlog) + DLQ growth-warning — 3중 감시
- 추출 3종(pdf/hwp/hwpx): DLQ has-messages(임계값 0)만 — 1중 감시

**개선 방향(추후)**:
1. 추출 3종에도 LLM과 대칭으로 큐 적체(backlog) 알람 추가 검토 — #62 당시
   추출 큐가 막혀 DLQ만 쌓이고 정작 "처리가 안 되고 있다"는 조기 신호는
   없었음. 큐 적체 알람이 있었다면 403이 DLQ까지 쌓이기 전에 더 빨리
   잡혔을 수 있음.
2. 추출 DLQ 임계값(현재 1건 이상이면 발동) 재조정 — 위 확장자 불일치
   (BadZipFile) 건이 정상 운영 중에도 상시 소량 발생할 수 있어, 지금
   임계값(0)으로는 알람 피로(매번 울림)를 유발할 위험. 정상 베이스라인을
   먼저 관찰한 뒤, "베이스라인 + 여유분" 방식(LLM growth-warning 알람과
   동일 패턴)으로 재설정 검토.

**현재 상태**: 미착수. #62 마무리 후 별도로 다룬다.
